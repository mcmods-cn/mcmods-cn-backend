# 导入终态通知只读诊断

此工具只检查明确指定数据库、schema、单一项目和最多31天的时间窗，最多返回10000项任务。整个业务查询在30秒超时、3秒锁等待限制的只读可重复读事务内运行，最后回滚。没有修复、补发或奖励重放模式。

先阅读 SQL，再为已获授权的目标执行，例如隔离测试库：

```sh
psql "$AUDIT_TEST_DATABASE_URL" -X -qAt \
  -v expected_database=mcmods_audit_test \
  -v audit_schema=public \
  -v project_public_id=example01 \
  -v since=2026-10-24T00:00:00Z \
  -v until=2026-10-25T00:00:00Z \
  -v max_jobs=1000 \
  -f tools/audit/import-notifications/diagnose.sql
```

输出只含任务状态和时间、公开项目标识、预期模板与保留意图/通知的计数，不读取邮箱、正文、源附件、令牌、预签名地址或余额。数据库名必须与实际连接一致；调用者须明确选择实际 schema。

`missing_retained_result_candidate=true` 表示目前既没有匹配模板的持久意图，也没有匹配通知。它不能证明历史漏发：队列和通知保留策略、账号删除以及同一任务的多个执行尝试都可能影响计数。反之，有旧意图也不能证明当前尝试已有通知，或收件人已收到。必须结合原任务尝试、源事件、保留/投递记录及当时的收件人事实，再形成逐项补偿方案；不能按当前收件人列表或当前奖励规则补造历史。

合成的当前任务、已批准来源及实际公开PNG使用主业务夹具建立，工具验证只读查询的正常结果与错误目标拒绝。生产诊断和修复均未执行。历史缺失行和保留清理的所有组合仍需在相应测试副本独立核对。
