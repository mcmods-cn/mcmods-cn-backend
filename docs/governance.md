# 三仓维护与验收台账

工作分支均为本地 `governance/nov21`。本页记录本次变更的依据、复跑方式和待验事项；[系统地图](system-map.md)用于查业务和权限入口。[历史材料](history/README.md)保留既有证据。

## 起点与工作顺序

2026-11-21 用 `git ls-remote --symref origin HEAD` 核实三个远端均以 main 为默认分支。三份原始 checkout 均在单独的干净 work 分支，与下列阅读基线一致。

| 仓库 | 本次开始的 main |
| --- | --- |
| exporter | `c61c8f952a8833b88a4c1aefa7a976efb0149528` |
| frontend | `e9948fde232581705fcedecbbf2a23312b4be726` |
| backend | `21724a42fd0dd84935fa0b4b7cf75c123a191500` |

M0 核实三仓和七个业务域。M1 优先处理可能丢失已确认消息的配置回滚、授权有效期及供应商数据边界。M2 按导入发布和配置读取的事务/页面边界收敛。M3 用单节点实际 JetStream 和隔离 PostgreSQL 检验两实例投递、长任务与本地降级。M4 在访客、合成管理员和普通编辑者的实际浏览器界面验证。M5 核对生产 ZIP、消费投影、包校验器和维护入口。M6 在独立 checkout 复核并记录发布与恢复条件。

验证机为 Linux amd64，5 vCPU、16 GiB 内存上限。初始 Go 1.26.6、Node 24.19.0/npm 11.17.0、JDK 17.0.21.1/Gradle 8.8，初始 Next 16.3.8/React 19.2.4。PostgreSQL 18.6、Redis 7.4.11、NATS 2.11.17 由本次固定镜像及独立数据库启动；队列专项另使用 go.mod 固定的 file-backed nats-server。源包为仓库记录 SHA 的真实 Fabric 样本，OSS 协议使用回环替身。真实供应商调用、邮件发送和线上部署不属于此次验证。

## 发现与证据

| 编号 / 影响 | 基线证据及根因 | 实现、验证或待验条件 |
| --- | --- | --- |
| Q1 · P0 已复现，共享 stream 数据丢失 | 候选 NATS 配置创建 stream；其他客户端收到 PubAck 后，候选配置保存失败会删除整个 stream。两个真实客户端在固定故障窗口观察到 stream 消失。 | 配置回滚只释放该候选连接和订阅。用原消息字节验证保留，检查旧配置仍工作。[队列恢复](queue-recovery.md) |
| Q2 · P1 已复现，长任务重投及本地阻塞 | 300ms AckWait + 900ms 合成工作观察到两次业务入口。原 `DispatchBatch` 预领 64 项串行执行，本地路径忽略任务 deadline/开关。 | 比较正常长任务入口次数、续期、死信、本地任务开关、两 dispatcher 和不同 attempt 的租约。在持久化端维持业务幂等，供应商计费仍有独立窗口。 |
| I1 · P1 已复现，重复批准重写目录 | 同一修订连续两次普通批准，第二次目录代数由 2 变 3。HTTP、ZIP 和嵌入图标 Worker 分别实现替代和投影。 | `publishCatalogRevisionsTx`，首次批准更新投影，重复请求只返回已发布状态。由 HTTP/PG 校验单次决策、目录代数、两种工作模式、归档及竞争。 |
| I2 · P1 已复现，公开配方图片不显示 | 浏览器直接访问 API 的 PNG 307 带 `same-site`，审核已经成功，图像请求被 Chromium 拦截。 | 复用 `anonymousPublicRasterRedirect`，只对确认可匿名读取的栅格图成功重定向设置跨源嵌入，签名重定向维持私有缓存。审核者预览和错误沿原规则。 |
