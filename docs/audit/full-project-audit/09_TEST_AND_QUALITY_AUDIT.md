## 测试缺口

优先补充：

1. 前端认证失效响应头、跨标签同步与导航栏清理；
2. 普通用户/管理员创建各项目类型后 Session 持续有效；
3. 编辑员授权、作者认领、团队关系变更和多来源撤销；
4. 模板通知各语言、旧调用方迁移、Outbox 重试；
5. 评论楼层并发与跨分页定位；
6. 文件/ZIP/log 分享安全边界；
7. 收藏夹 `.mrpack` 结构、报告和过期；
8. Redis 故障、多实例权限缓存和限流；
9. JetStream 重投递、消费者重启和死信。
10. Markdown 草稿区分无记录与数据库故障；用户文件列表行错误和额度查询故障；
11. 项目创建禁止授权必须用真实数据库断言，不能只依赖函数体 AST 字符串；
12. 外部团队角色未知值默认不授权，移除 `Supporter -> developer` 的风险断言；
13. 作者/团队关系编辑保留 pending/rejected 审核记录，并发保存不重建稳定关系；
14. 权限组线路并发升降级、同时授权/撤销和行读取错误。
15. `internal/security/token.go` 的签名篡改、算法/类型、时钟边界、Claims和Bearer解析直接单元测试。
16. 用真实项目 INSERT/审核/删除验证 `submitted_by` 会更新 `user_content_creation_facts`；
17. 构造错误 daily/totals/action_counts 后运行校准，断言全部字段精确一致，而非只匹配 `greatest` SQL 片段。
18. 对接近8 MiB且完全不同的Markdown前后文本执行资源上限/基准测试，断言不会产生约256 MiB单请求分配；
19. 模拟成长投影在原始活动提交后的失败，验证事件可幂等重放且不会永久少计。
20. Yggdrasil完整authenticate-refresh-join-hasJoined数据库集成，并注入Token更新时间失败，验证join不会出现客户端失败但服务器成功的半提交状态。
21. 同一用户并存comment/message/upload多条限制、不同创建顺序和缓存命中测试，确认任一匹配限制均不会被遮蔽；
22. 注入反滥用状态写入、事件/指纹写入、机器人规则扫描和挑战metadata失败，验证可观测且降级策略明确；
23. 查询计划测试使用受控大数据并断言索引/扫描行数，不以“EXPLAIN非空”作为性能通过。

## 负载测试结果的统计语义会掩盖小比例失败（TEST-050）

`scripts/load-test.mjs`把所有4xx统一计入`clientErrors/errorRate`，因此反滥用和爬虫场景中预期的403/429被报告为68%至75%“错误率”；另一方面`round()`只保留两位小数，23/14613个网络超时以及29/15245个5xx/网络失败又都显示为`errorRate: 0`。脚本只在5xx或网络错误时退出非零，不会按场景断言允许的状态码、预期风控码或最低成功量。它还在每个请求前重新构造所有请求池和混合数组，负载发生器自身分配会污染高并发结果。现有34份脚本/结果已逐份核对，计数恒等式均正确，但只能作为带人工解释的历史样本，不能作为自动性能门禁。

`scripts/query-analysis.sql`选择“第一名用户”而非参数化的代表性高基数用户，只测目录`OFFSET 20`；`anti-abuse-query-analysis.sql`仅执行不含`ANALYZE/BUFFERS`的计划估算。因此这两份查询辅助脚本也没有覆盖十万、百万和千万行分布，不能替代本报告记录的大数据量静态风险。
