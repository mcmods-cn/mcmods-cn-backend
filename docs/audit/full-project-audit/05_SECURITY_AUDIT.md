# 安全审计

## 总体评价

认证、权限、Cookie、来源校验、文件访问和 ZIP 处理的基础实现较强。未确认发现 SQL 注入、项目创建者权限旁路、公开原始日志下载、Markdown XSS 或 SSRF 私网访问漏洞。下列结论不代表渗透测试或第三方供应链审计已经完成。

## 认证与 Session

- Session Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产/TLS 下启用 `Secure`。
- Cookie 认证的变更请求检查来源，CORS credentials 仅允许明确前端 Origin。
- Session 只校验 `auth_version`，普通授权变化不会错误注销用户。
- 可选认证向前端发出“已携带 Session 但失效”的统一信号，修复了 UI 假登录状态。

结论：设计符合当前业务规则。真正的封禁、停用、密码修改和强制退出仍须覆盖回归测试。

补充：状态修改 Handler 目前忽略提交后的认证/权限版本缓存刷新错误（SEC-004）。数据库事实正确，但共享版本缓存最长 10 秒的旧值会形成短暂撤销窗口；这与“安全状态应立即使旧 Session 失效”的目标不完全一致。普通资料设置和权限组线路变更也忽略权限版本刷新错误，虽不应注销 Session，但会让授权变化短暂滞后。

## RBAC 与项目权限

- 项目提交者不参与长期管理权限计算。
- 用户权限、全局 RBAC 和项目 ACL 使用版本化缓存键；权限事实回源 PostgreSQL。
- Redis 故障时不会因为缓存不可用而默认允许高风险操作。
- 项目作者/团队关系状态和 `permission_granting` 标志进入派生权限判断，待审核/展示性署名不授权。
- 后台手工授权保留但需要管理员权限和审计。

未发现 `created_by == currentUser` 或 `submitted_by == currentUser` 对已发布项目的通用管理后门。

但禁止自动授权的 AST 测试只检查指定函数体内的 SQL 字符串，辅助函数写入可以绕过，不能替代数据库集成验证。另有一条已确认权限语义风险：外部作者团队导入把未知成员角色默认映射为 `developer`，而该角色在 Schema 中 `permission_granting=true`。展示性角色必须默认不授权，只有明确白名单角色才能进入派生开发者权限。

权限组线路升降级还存在事务外读取后全量替换的并发窗口；这可能覆盖并发授权或撤销，详见 `BUG-004`。

## 公开用户资料与历史可见性

`/api/v1/users/{id}/showcase` 和 `/contributions` 是可选认证的公开路由。作品与上传列表会检查当前公开状态，但最近贡献历史只检查历史变更请求已经批准，并直接从修订快照取名称。目标后来被删除、隐藏或变私密时，当前代码仍可能返回原名称和对象类型。需要明确产品保留政策；默认治理安全边界应复核当前目标可见性，完整历史只在受权限保护后台提供。

## 输入与 HTTP

- JSON 请求体统一限制为 8 MiB并拒绝未知字段。这个全局上限不能替代各领域的更小内容上限；Markdown差异统计在接近上限时存在 `SEC-007`。
- 前后端均设置安全响应头，前端代理使用 nonce CSP；生产配置包含 HSTS。
- 前端nonce和`strict-dynamic`实现本身有效，但`connect-src https:`仍允许向任意HTTPS来源外连，图片、媒体和字体来源也同样宽泛；该防御纵深缺口登记为`SEC-045`。
- 错误响应通常经过统一错误结构，不回传内部堆栈。

仍有局部 Handler 直接返回不同语言文案，主要是接口一致性和信息治理问题，不是已确认的注入漏洞。

## Markdown 与富文本

- ReactMarkdown 配置跳过原始 HTML。
- 链接只允许 HTTP(S)、站内路径和锚点。
- 楼层和 Sticker 在语法树/文本节点阶段处理，代码和链接节点不替换。
- Sticker 数量有限制，避免单篇内容触发大量查询/渲染。

### PlantUML 隐私风险

PlantUML 默认启用并可将编码后的图表源发送到公共 `plantuml.com` 服务。虽然不是脚本执行漏洞，但用户输入的图表内容会离开 MCMods 域。建议生产默认使用自建服务，或显式告知并让用户选择。问题编号 `SEC-001`。

### Markdown差异资源上限

评论、作者说明和服务器正文编辑会对旧文本与新文本计算精确字节差异。实现按两份文本总长度分配整型frontier；在全局8 MiB请求上限下，最坏单请求临时内存约256 MiB，并可能执行数千万次迭代。该问题不依赖HTML执行或未授权访问，普通登录写权限即可触发，编号 `SEC-007`。

## 文件、OSS 与下载

- 文件记录和对象访问集中校验所有者、可见性、扫描状态与用途。
- 私有文件响应禁止公共缓存；公开前要求 `clean` 或受信任衍生状态。
- 项目下载关系是例外：创建关系只要求OSS记录 `status='active'`，普通上传完成时仍可能是 `scan_status='pending'`。下载端点会阻止非clean文件，但列表和项目更新事件已经把它当作已发布，见 `BUG-032`。
- 外部文件镜像校验扩展名、许可证、大小和已有 SHA-1/SHA-512，并使用安全对象路径。
- 外部 HTTP 客户端拒绝私网、回环和不安全重定向，限制响应体大小与跳转次数。

### 导入包内容身份与图像解码

- Mod导出包和嵌入图标目录共用全局SHA唯一的 `catalog_import_packages`，但冲突写入会替换既有包的源文件/上传者；上传完成只核对客户端提供的OSS哈希元数据，实际内容哈希到Worker才计算。该可变内容寻址记录允许跨用户干扰既有任务，编号 `SEC-009`。
- 嵌入图标先用 `image.Decode` 完整展开PNG，再检查1亿像素阈值；最多8条并发构建可在拒绝前放大为多GiB内存，编号 `SEC-010`。
- 修复应让包记录在服务端实际哈希验证后不可变，并在完整图片解码前用 `DecodeConfig` 和共享内存预算拒绝危险尺寸。
- 外部元数据供应商BaseURL允许改为任意公共HTTPS主机，而更新时会自动保留原密钥；Worker随后向新主机发送Authorization/API Key。配置写权限因此可转化为供应商密钥读取能力，编号 `SEC-011`。

## 日志分享与 ZIP

- 公开短链只读取 `ready`、未过期、未删除的脱敏副本。
- 脱敏失败关闭；公开访问不会退回原始文件。
- 粘贴模式下载由后端拒绝，而不只是隐藏按钮。
- ZIP 拒绝绝对路径、`..`、重复路径、符号链接/设备文件、加密包、嵌套 ZIP、过高压缩比、文件数/尺寸/目录深度超限。
- 公开页面设置 noindex/noarchive；日志作为纯文本展示。

## 反滥用与限流

Redis 可用时提供跨实例限制；故障时使用本进程固定窗口。配置会拒绝“未配置 Redis 但声明多副本”的启动方式，但运行期间 Redis 故障会让每个实例各自拥有额度，等效限额可能按副本数放大。建议对游客长保留日志、登录和昂贵导出采用数据库兜底计数或故障关闭策略。问题编号 `SEC-003`。

账号限制当前只加载一条最高优先级/最新记录，缓存也不区分action；同账号多条cooldown/no_comment/no_upload等并存时，无关的新限制能遮蔽仍有效的旧限制。该问题编号 `SEC-008`。此外自动限制落库和机器人规则读取存在静默失败路径，见 `ARCH-007`。

## Minecraft服务器探测

地址解析会检查域名返回的全部IP均为公网地址，并直接拨号已验证IP、保留原Host做Minecraft握手，因而没有确认DNS重绑定或RFC1918 SSRF。风险转移到恶意公网服务端的响应资源消耗：Configuration注册表解析可从极小伪造计数预分配百万字符串容量，Fabric路径允许64MiB数据派生500万字符串，见 `SEC-014`。此外客户端可伪造模组探测来源和置信度，见 `BUG-030`。

## 异步安全

- Outbox、已处理事件和死信表具备幂等基础。
- 本机 JetStream 不可用，无法验证消息持久化、重投递和多消费者行为。
- Core NATS 直发只适合作为明确禁用 Outbox 时的降级路径，不能成为关键任务的生产唯一记录。

## 供应链与未执行测试

- `go mod tidy -diff` 无差异，只证明模块图一致。
- 当前环境没有 `govulncheck`；pnpm audit 因仓库采用 package-lock 且当前 npm 可执行环境不可用而未完成。
- Race 测试因 Windows 缺少 C 编译器无法运行。

这些项目必须记为“未验证”，而不是“无漏洞”。

## 蓝图解析与公共转换资源边界

- `SEC-026`：Sponge解码把不可信Palette数值直接当切片最大下标，在验证索引密度和预算前分配 `maxPalette+1`，小文件即可触发巨额内存申请。总体积限制不能防住该路径。
- `SEC-027`：任意登录用户都能为任意公开蓝图创建缺失格式转换任务；该路径没有对象级授权，也没有用户/全站原子配额，而一次任务可读512 MiB并处理数百万方块。
- 蓝图公开render和cover的缓存边界本身是正确的：只有已批准内容使用公共缓存，所有者/管理员查看非公开内容时使用private/no-store并设置认证Vary。

### 用户文件额度竞态

`SEC-028`：日上传量和总存储量通过无锁SUM检查，错误被当作0，校验与文件登记不原子。数据库故障或并发完成都能绕过额度；这与前端显示的额度无关，必须在PostgreSQL原子预留和结算。

## 已确认安全边界的复测建议

- IDOR：以两个普通用户分别访问收藏夹导出报告、举报附件、私有文件和后台技术关系。
- 权限：提交者无项目角色时调用编辑、文件、审核、成员和删除接口均应 403。
- Markdown：脚本、HTML、恶意 URL、代码块内 Sticker/楼层文本均不执行/不替换。
- ZIP：路径穿越、加密、嵌套包、符号链接、高压缩比和超文件数样本全部拒绝。
- Session：密码修改/封禁后旧 Cookie 失效，可选认证同时发出前端清理信号。
- SSRF：DNS/重定向到回环、RFC1918、link-local 和云元数据地址全部拒绝。
### 站内OSS图片复用缺少对象级授权（SEC-012）

外部图标镜像器允许把配置公共端点下的现有对象直接作为导入结果，但只验证对象Key存在、active/clean、图片类型与内容哈希，没有验证所有者、业务类别或公开用途。已知其他对象Key可被跨项目复用；是否直接暴露内容还取决于部署中的桶ACL和项目图标访问方式。应把“内容安全”与“调用者有权公开该对象”分开校验。

### Mod入向关系跨项目写入（SEC-013）

Mod快照把入向关系当作可编辑数据。保存当前Mod会先删除其他已发布Mod指向它的全部关系，再根据当前请求到那些来源Mod中创建关系组/关系，过程中没有来源项目权限检查；对称关系还会删除目标项目的反向记录，结尾全局清理空组。应立即把入向关系改为只读派生数据，并给关系写接口增加来源项目级授权及跨项目安全测试。

### 自动更新配置GET具有越权写入和跨站GET副作用（SEC-015）

`projectAutomation` 对GET只要求 `project.auto_update.view`，随后 `writeProjectAutomation` 会在事务中插入缺省设置；若找到Modrinth/CurseForge来源，还会把Minecraft版本同步默认设为启用，并把查看者写成 `configured_by`。`project.auto_update.view` 与 `project.auto_update.configure` 是独立权限，因此只读角色可以通过一次GET改变调度事实；页面预取或携带SameSite Lax Cookie的顶层导航也不具备写操作应有的CSRF语义。默认值应在受权项目/来源建立事务中生成，或GET只合成未持久化响应；启用必须使用受保护的PUT/POST。

### 爬虫AI每日预算非原子且查询失败时放开预算（SEC-016）

每个run先执行一次当日token SUM，错误被忽略而 `used` 保持0；之后每个locale调用前只比较进程内局部值。并发手工run、多实例Worker或租约重复执行都可以各自认为拥有完整预算，单次AI调用也没有按剩余额度原子预留。配置的 `ai_daily_token_budget` 因此不是硬限制，数据库瞬时故障反而放开全部额度。应在PostgreSQL以日期+任务原子预留预算、失败结算，并让读取/预留失败关闭；同时限制输入和模型最大输出。

### 游客可伪造并无界放大在线访客集合（SEC-017）

`POST /api/v1/site/presence` 对16至128字符的 `visitorId` 直接信任并做SHA-256，不把它绑定到服务器签发的匿名标识、IP或会话，也没有端点级唯一访客预算。攻击者可以持续提交不同值，在五分钟窗口内任意抬高后台在线统计；Redis ZSET和进程内 `presence` map都会为每个伪造值保存成员，其中本地map只按时间裁剪、没有容量上限。应使用服务端签名匿名Cookie或稳定的IP/UA风险标识，叠加统一限流和全局/单IP基数上限；Redis故障回退也必须有有界容量。

### 登录用户可建立无界SSE连接（SEC-018）

Realtime Hub为每条SSE连接分配一个32项channel和一个20秒ticker/goroutine，但端点没有单用户、Session、IP或全站连接上限。同一有效账号可以并发建立大量长连接，持续占用内存、goroutine、文件描述符和代理连接；广播时还要遍历该用户全部channel。应按Session/用户/IP限制连接数，配置全站预算和空闲/最大连接寿命，并暴露拒绝及连接指标。

### 站点Logo只检查魔数且绕过统一图片管线（SEC-019）

Next上传路由在 `formData()` 完整解析后检查File size和PNG/JPEG/GIF/WebP起始字节，未实际解码、未验证宽高/像素/GIF帧数/总解码量，也不移除元数据。5MiB压缩图仍可声明极大尺寸或高复杂度动画，随后被长期公开缓存并由每个访客浏览器解码。应复用后端OSS图片验证、像素和动画预算、重编码/元数据策略；请求体也应在formData物化前由网关和路由限制。

### API访问日志持久化OAuth临时凭据（SEC-020）

`logAccess` 默认把所有 `/api/` 请求的完整 `RawQuery` 写入 `app_logs.payload.query`，只有Yggdrasil路径被清空；OAuth回调 `/api/v1/auth/oauth/{provider}/callback` 明确从查询串读取 `code` 和 `state`。这会把一次性授权码和反CSRF状态保存到默认保留90天、可由日志管理员搜索的数据库事实中。即便授权码通常短时且单次使用，也不应进入持久审计载荷。访问日志必须采用端点级字段白名单或统一敏感参数脱敏，并覆盖OAuth、密码重置、邀请和未来任何Token查询参数；不能继续用单个路径前缀例外维护。

### 默认用户种子会在每次启动重新激活账号（SEC-021）

`SeedRBAC` 在每次后端初始化执行，`seedDefaultUsers` 对用户名冲突无条件把邮箱、`email_verified` 和 `status` 更新成源码默认值。管理员若通过安全流程停用或删除默认 `admin`，下一次进程重启会把账号恢复为 `active`；同样会恢复 `autobot` 和 `guest`。这是持久安全状态被启动种子覆盖，而不是权限缓存问题。系统身份应以不可登录的专用主体建模；可登录管理员只在空库创建，后续状态必须由账号安全服务维护，种子不得覆盖。

### 公开内容统计泄露登录用户最近访问记录（SEC-022）

`GET /api/v1/content-metrics/{publicId}` 只使用可选认证，任何访客均会收到最近八名登录访问者的公开ID、用户名、头像和精确 `last_seen_at`。查询没有读取用户的在线状态隐私设置，也没有单独的访问记录公开授权；用户仅浏览一个公开项目，就会被公开列入该项目的最近访客。应默认不公开个体浏览事实，若产品确需展示则必须有明确opt-in、较粗时间粒度和权限/屏蔽关系过滤。

### 浏览统计端点允许无界pageKey写入并被明确排除反滥用（SEC-023）

`POST /api/v1/content-metrics/{publicId}/view` 对游客开放，`antiAbuseAction` 又明确排除全部 `/content-metrics/`。请求者可以为同一项目持续提交不同的最长200字符 `pageKey`，服务端会永久插入新的 `content_project_pages` 哈希行，同时增加浏览计数和刷新队列。页面数量还作为热度公式除数，因此攻击者既能制造无界存储/队列写放大，也能操纵项目热度。必须由服务端按目标类型校验有限页面类别，接入读/写频率和基数预算，并使统计事实可清理、可校准。

### 自动角色轨道会覆盖管理员手工权限（BUG-059）

等级变化调用 `SyncTrackRole`，它按轨道取得所有role ID后直接删除用户的全部对应 `user_role_bindings`，再插入当前等级角色。绑定主键和记录没有授权来源，无法区分等级派生与管理员为特殊情况手工授予；下次任务奖励升级或管理员调整等级会删除手工授权。应保留手工配置线路，以来源化绑定或独立派生关系精确替换等级来源，权限合并时保留其他来源。

### 后台权限保存会抹掉角色到期时间与来源（SEC-044）

`PUT /admin/users/{id}/permissions`先删除目标用户全部角色绑定，再把`group.*`项目仅按角色代码插回；读取响应和前端草稿都没有角色级`expires_at/context`。请求里的`allow=false`、有效期和context对group项也被忽略，仍会绑定角色。临时`banned`角色因此可能被重建成无期限、无`ban:<id>`来源的角色；到期Worker按context删除时无法命中，用户状态恢复后仍受永久拒绝。其他临时/等级/手工来源也会被合并成一条不可追踪事实。这不是“管理员可手工配置”的必要能力：手工应急授权必须保留，但应使用来源化、差异化写入并明确展示每条来源/有效期，禁止一个界面保存静默改写其他安全子系统的事实。

所有角色/权限写入提交后又忽略`refreshPermissionVersion/refreshRBACVersion`错误；持久版本最终正确，但共享缓存可短暂保留旧规则，继续扩展既有`SEC-004`证据。

### 收藏夹导出限额可被并发请求绕过（SEC-024）

`handleCreateFavoriteModpackExport` 在事务开始和插入任务之前，分别统计用户活动任务、每日任务和同收藏夹冷却窗口；这些检查没有用户级advisory lock、限额桶行、唯一约束或可串行化事务。两个或更多并发请求可以读取相同旧计数并全部创建任务，绕过单用户并发数、每日次数和短时重复导出限制，进而放大远端元数据请求、Worker和OSS资源。应把计数与占位收敛到同一原子配额事务，数据库冲突返回稳定限流错误。

### Modrinth整合包条目身份只验证URL路径形状（SEC-025）

`modrinthIndexMods` 在每个 `downloads` 字符串中仅用正则寻找 `/data/{project}/versions/{version}/`，不解析URL，也不验证HTTPS和 `cdn.modrinth.com` 主机。外部整合包作者可写入 `https://attacker.example/data/victim/versions/fake/file.jar`，导入后该条目仍被标为provider=modrinth、project=victim；发布时又按该ID解析站内Mod。下载地址本身不会由此被站点抓取，但项目身份和包含模组关系可以被伪造。应复用MRPack导出端的严格CDN URL解析并验证路径ID/元数据归属，不能把路径片段当身份凭据。

### ESA私有源站下载链接不执行后端声明的过期时间（SEC-029）

ESA模式返回的是公开端点加稳定对象路径，`expires_at`只出现在API响应中，没有被编码为边缘可验证的签名或Token。本站只能保护“取得链接”这一步，无法撤销已经取得的链接。必须使用边缘验证的短期签名，或让私有文件持续经过本站授权下载端点；部署文档不能把外部配置假设当作代码已经实现的过期授权。

### GIF可信判定没有验证完整动画（SEC-030）

通用栅格验证只解码GIF首帧，因此帧数、总解码量、动画时长和后续畸形帧没有进入clean/trusted判定。应复用带总预算的完整GIF解析器，并用多帧炸弹、后续损坏帧验证失败关闭。

### 评论回复/插眼子路由绕过目标可见性（SEC-031）

评论目标列表、线程、楼层和附件下载会解析所属对象的公开性，但直接回复列表只验证评论为published/deleted；原观察者的插眼列表在目标解析失败后仍返回评论正文。项目转私密、隐藏或权限撤销后，知道评论ID的人仍可能读取回复。所有评论子资源必须先通过同一目标可见性解析器，批量列表也不能把目标失败降级为可读空壳。

### 插眼额度和整棵线程存在资源放大（SEC-032、SEC-033）

插眼2000条上限采用无锁COUNT后upsert，可并发突破。公开线程接口又可一次返回深度256内的全部后代，并对每项聚合表态、权限和附件。需要原子额度预留以及带节点/字节预算的线程定位分页，不能把数据库深度约束当作响应规模限制。

### 私有皮肤与公开玩家档案的隐私语义冲突（SEC-034）

玩家档案只校验档案visibility，纹理加载不校验asset visibility并始终返回哈希和公开纹理URL。因此private皮肤若仍装备在public档案会被匿名下载。系统必须明确组合规则：要么公开档案意味着当前纹理公开并在设置时显著提示/阻止冲突，要么公共档案使用独立受控快照且不返回私有asset元数据；当前 `canUse=false` 不能阻止实际读取。

## 收藏目标可见性与资源配额

- `SEC-035`：收藏目标只按 `(entity_type,public_id)` 查询 `public_routes`，没有复用各项目的可见目标解析器。用户可把已知ID的待审Mod/整合包或他人私有蓝图加入自己的收藏夹，再由本人列表读取名称、slug、标题、图标等元数据；这是跨审核/隐私边界的间接对象引用漏洞。
- `SEC-036`：收藏夹数和收藏项总数没有数据库或应用额度。统一反滥用只限制请求速率，不限制长期存量；列表和选择器又一次加载全部集合/条目，单用户可持续制造数据库、响应和前端渲染放大。

## 社区内容引用泄露隐藏项目（SEC-037）

社区内容保存项目引用时只查询 `public_routes(public_id,entity_type)`，没有复用目标类型的公开/审核/私有可见性解析器；读取引用时又直接联接Mod、整合包和简单项目名称，没有状态过滤。只要知道公开随机ID，登录用户就能把待审、隐藏或已软删除目标写进自己的内容并读回名称/slug；一个原本公开的引用目标后续隐藏后也仍会从已发布社区内容泄露元数据。写入和每次读取都应经过统一目标可见性校验；不可见引用只能返回安全占位，不能把社区文章的公开性当成被引用对象的授权。

## 公共读取可触发无配额AI任务（SEC-038）

统一内容GET是可选认证公共路由。当请求语言属于八个可编辑语言、但目标内容尚无该翻译时，它会以actor 0、`quotaBacked=false`自动创建并发布AI翻译任务。去重只覆盖queued/running/retrying以及仍待审核的completed任务；failed任务可被下一次读取重新创建。攻击者无需账号即可遍历公开内容与语言，消耗供应商额度、任务表、日志和Worker资源。自动补齐应由有界后台计划或受限显式操作触发；公共读取只能返回回退内容/缺失状态，不能成为付费写入口。

## 草稿JSONB存储可被普通用户无界放大

普通注册角色默认获得30天草稿保留权限。草稿端点没有单用户条数、总字节或历史上限，每个唯一`draftKey`可写入接近通用8MiB限制的JSONB，反复完成同一key又可持续新建历史行。这是需要登录但成本低、持续30天、同时放大WAL/备份/清理的存储耗尽路径（`SEC-043`）；应将业务大小上限与用户原子存量配额放在后端权威边界。

## 经济整数溢出与等级权限残留（SEC-039、SEC-040）

- `SEC-039`：转账税使用`request.Amount * int64(taxBPS)`后才转float，商店总价使用`unitPrice * quantity`，均没有checked arithmetic或业务最大金额。int64回绕可令税为负、收款额大于付款额，或令巨额商品按较小正数成交。数据库非负约束只能拦住部分回绕结果，不能保证守恒。
- `SEC-040`：等级role track切换或清空时，更新逻辑只对新track调用`SyncTrackRole`；旧track角色绑定保持不变。角色绑定本身又没有来源，用户可能在管理员认为已停用旧轨道后继续持有权限。必须在同一事务识别旧/新轨道、按来源精确重算，并只递增permission version而不注销Session。

## 表情图片隐藏元数据未清理（SEC-041）

表情图片会完整读取并安全解码，但验证后的原始PNG/GIF对象被直接改为公开`sticker`来源。代码没有重编码PNG，也没有移除PNG文本块、色彩配置或GIF注释等非像素元数据；公开内容端点最终向访问者签发原对象访问。具备上传权限的操作者若选用了带作者、路径或工具信息的图片，这些隐藏信息仍可被下载。应在隔离处理中生成经重编码/元数据清理的派生公开对象，原上传保持私有；GIF需使用能保留动画且可验证元数据策略的处理器。

## 可信代理位置解析的确认结论

`requestClientLocation`不会仅因请求携带`X-Forwarded-For`或CDN头而信任它们；TCP对端必须落入配置的可信CIDR。链解析从右向左去除可信代理并在畸形值时回退对端，关键反伪造行为已有单元测试。没有发现直接的客户端IP伪造旁路。配置层对非法CIDR会静默忽略，结果是少信任而不是扩大信任；上线时仍应让边缘代理清除所有客户端自带的`Ali-*`、`True-Client-IP`和`CF-IPCountry`头。

## 举报目标可见性没有失败关闭（SEC-042）

统一举报首先只查询`public_routes`，随后直接从评论、Mod、简单项目、服务器、蓝图等业务表抓取快照。评论没有状态或所属对象可见性条件；Mod、简单项目和服务器没有审核/公开状态条件；蓝图没有visibility/owner条件。`public_routes`是稳定身份目录而不是授权证明，软删除或隐藏通常也不会移除该路由。结果是已知公开ID的登录用户可以对自己无权查看的对象创建举报、探测其存在并让完整正文/地址/关系快照进入治理留存。虽然快照只向额外具备`report.snapshot.view`的审核者返回，创建者仍不应拥有触发私有内容复制和治理流程的对象权限。举报写入前必须调用与公开详情相同的类型化可见性解析器；历史上已公开后隐藏的对象应走明确的受权旧举报规则，而不是只凭路由存在放行。

## 浏览器断点上传的账号隔离（SEC-046）

Mod资料导入会把完整ZIP与断点元数据保存在IndexedDB。Bearer Token路径从JWT `sub`派生任务键，但站点正常Cookie Session统一使用固定`cookie-session`，派生逻辑因此统一回退为`session`。同一浏览器切换账号后，后一个账号会命中前一个账号相同项目/版本的本地任务，并可能用自己的凭据重新上传前一账号的文件。服务端权限只能拦住旧ticket/job，无法隔离尚未取得服务端身份的本地文件。任务主体必须来自已认证用户快照，并在账号变化时精确隔离/停止；恢复端同时验证服务端所有权。
## 远程Iconfont脚本白名单边界（SEC-047）

前端会把构建期配置的Iconfont URL直接作为可执行脚本注入。协议被限制为HTTPS，但主机校验使用`hostname.endsWith("alicdn.com")`，没有域名标签边界，因此非阿里域名如`evilalicdn.com`也能通过。当前输入不是普通用户可控，风险集中在构建配置和供应链；仍应改为本地打包或精确主机/带点子域匹配，并用CSP、SRI与启动配置校验缩小执行边界。
