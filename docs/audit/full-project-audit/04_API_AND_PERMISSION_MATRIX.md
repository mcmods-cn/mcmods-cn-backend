# API 与权限矩阵

## 路由统计

| 方法 | 数量 |
| --- | ---: |
| GET | 244 |
| POST | 125 |
| PUT | 71 |
| DELETE | 35 |
| PATCH | 14 |
| 合计 | 489 |

守卫统计：222 条路由要求明确权限，146 条要求登录，98 条使用可选认证，23 条为公共路由。公共写入主要是注册、登录和邮件验证码；允许游客的其他写入包括粘贴日志、在线状态和浏览/下载指标，均需要独立限流与输入约束。

全部 489 条注册路由的方法、路径、外层守卫、权限、Handler 和注册行号见 [modules/API_ROUTE_INVENTORY.md](modules/API_ROUTE_INVENTORY.md)。该机械清单只证明外层注册关系；对象级权限、限流、事务、表、缓存和副作用必须进入 Handler 审查，未逐项确认的路由不能因为挂了中间件就标为安全。

## 权限获取线路

### 项目编辑员

```text
project_editor_application approved
  -> project_editor_assignment
  -> permission/project ACL version bump
  -> next request resolves new access
```

只作用于申请的 `project_type + project_id`，不显示为作者或团队成员。

### 已认证开发者

```text
approved personal author claim
  + approved permission-granting author/project relation
  OR approved team membership + team/project relation
  -> derived project developer access
```

团队不能被认领，团队成员引用作者实体而非用户。每个个人作者最多存在一个审核通过的认领；同一用户可以认领多个作者。

### 后台手工授权

手工 `project_developer.[ProjectID]` / `project_editor.[ProjectID]` RBAC 绑定保留，供纠纷、紧急维护和特殊项目使用。该路径必须由后台权限保护、记录审计并只递增权限版本，不能由项目创建 Handler 调用。

## 关键资源接口边界

| 资源 | 读取边界 | 写入边界 | 审计结论 |
| --- | --- | --- | --- |
| 全局资源 | 后台指定权限；普通资源响应不回传技术关系 | 现有绑定权限 | 后端校验存在，不只依赖前端隐藏 |
| OSS/文件 | 所有者、公开状态、扫描状态、对象用途 | 登录、额度、类型/魔数 | 未发现公开原始日志或私有对象旁路 |
| 日志分享 | `ready` 且未过期/删除 | 文件模式登录；粘贴模式限流 | 粘贴下载后端拒绝 |
| 评论楼层 | 对象可见性和评论状态 | 登录/反滥用/对象评论权限 | 定位接口不跨对象泄露 |
| 作者/团队关系 | 公开展示与后台详情分层 | 独立高风险权限 | Handler 内 OR 权限检查为有意设计 |
| 系统日志 | 管理权限 | 无公共写入 | 后台读取真实运行日志缓冲 |

## 特殊 Handler 内权限检查

作者关系管理路由使用登录守卫，Handler 内部再校验 `project.authorship.manage` 与 `project.team_relation.manage` 的逻辑 OR。这是因为通用中间件表达单一权限，属于必须保留的授权边界，不应误判为漏挂权限中间件。后续若增加通用 `requireAnyPermission`，可以迁移，但当前实现必须保持失败关闭。

## 认证失效协议

- 没有携带 Session：可选认证正常按游客处理。
- 携带但失效：后端清 Cookie，并返回统一认证状态响应头。
- 前端 API 层收到后清理内存用户、缓存与跨标签页状态。
- 必须登录的写接口返回 401；权限不足返回 403。
