# 模块、角色与用户旅程核验

本报告对应本次实际前后端代码，执行结果由 `VERIFICATION.md` 汇总。角色是能力组合，
不是把所有登录用户、提交者或作者都视为项目管理员。项目操作以
`effective_project_access`、明确编辑员/认领关系及服务端权限为准。
“真实 PG”表示专用 PostgreSQL 中执行生产查询/Handler/Worker；外部 OSS、上游项目
提供者、邮件与 AI 可以是本地可控替身。它不等于生产数据或真实供应商验收。

## 已实施的体验补全

- 读取失败保留错误并提供 Retry；必须读取现有内容才能安全保存的编辑器在读成功前禁止写入。
- 上传、提交、保存和删除以同步操作守卫配合可见 busy 状态；失败保留输入及已上传文件 ID。
- 搜索/筛选/语言切换保留合理 URL 上下文；越界页在总数确认后规范化，旧请求结果不能覆盖新 scope。
- 原生对话框补焦点约束、Escape/关闭及恢复；移动视口、长内容、键盘与触摸操作按实际浏览器场景验证。
- 分类续读、附件单项重试、翻译发布失败状态与手动恢复接入原有界面，不创建不可达页面或伪成功接口。

受控 API 浏览器测试验证的是实际生产 React 界面的交互与错误恢复；数据库集成验证的是
真实项目代码与专用数据库。两者不自动组成“全部用户旅程已真实联通”的结论。
当前实际前后端联通只覆盖另列明确的旅程，不将每行矩阵都标为浏览器验收通过。

## 需要运行证据或产品决策的范围

| 优先级 | 范围 | 缺少的条件与决策 |
| --- | --- | --- |
| P2 | 真实 AI 语义质量、供应商用量/费用与公网可用性 | 专用测试凭据、允许的数据范围、明确费用上限及人工质量标准；本次不调用付费服务。 |
| P2 | 生产容量、NATS retention、备份恢复与跨实例故障演练 | 只读运行证据、容量/保留目标与明确隔离演练授权；不根据几行测试或配置存在推断健康。 |
| P3 | 通知邮件交付保证 | 当前邮件/实时广播的 best-effort 行为及外部失败是否须升级为单独持久交付承诺，需明确业务要求；通知数据库事实与入队原子性已分别核验。 |
| P3 | 所有任务族统一取消或付费请求撤销 | 已发送请求不能由本地取消保证未计费；需按领域定义终态/恢复规则，不新增通用“取消成功”假响应。 |
| P3 | GPU 长时运行、低端移动设备及全部长译文人工验收 | 代表设备/字体/语言与时长；硬预算、解析正确性和已有浏览器检查不证明所有设备性能。 |

不把以上边界作为跳过可完成修复的理由。新增缺陷、具体修复与测试见稳定 ID 问题台账；
候选风险与已确认缺陷分列，不以功能新增数量或静态扫描警告数衡量交付。
