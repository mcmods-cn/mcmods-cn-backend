# 审核结果通知与审核决定原子提交（CMP-003）

整合包、六类资料项目（插件、地图、资源包、光影包、数据包、附属项目）和作者资料的独立审核，过去先提交审核决定，再单独写入提交者的结果通知。通知意图写入失败会留下已批准/驳回但没有结果通知的状态；重复审核返回冲突，不能重建缺失意图。

上述三个处理分支现在通过同一个 `pgx.Tx` 写入原有的提交者结果通知，再提交审核决定、公开投影、关联关系、审核事件和活动意图。任何结果通知意图写入错误都会回滚事务并返回明确的 HTTP 500。订阅者通知仍有其独立用途，不能替代提交者结果通知。

保留原有 `notification.direct` 事件、`review_approved` / `review_rejected` 模板、接收者、actor 0、链接和模板参数。重复决定仍返回 409；已经删除且没有接收者的账号维持原先无通知的规则。权限、自审限制、奖励政策和审核状态机没有改变。通知意图不等于接收者已收到通知。

回归使用真实 HTTP、当前迁移创建的隔离 PostgreSQL 表和普通提交者/独立审核员。针对八类对象的批准和驳回分别注入只作用于结果通知的 `XX001` 故障，检查明确的错误与业务、关联、审核、outbox、权限、通知及奖励事实零变化；移除故障后正常审核一次，重复请求无额外效果。实际 `NotificationWorker` 按同一事件 ID 消费两次，只生成一条有正文的结果通知。该层直接调用业务消费者，没有证明 NATS 传输或真实浏览器操作。

执行入口（采用任务自己的隔离数据库；不使用生产连接）：

```sh
APP_ENV=test MCMODS_RUN_DB_INTEGRATION=1 \
DATABASE_URL="$AUDIT_TEST_DATABASE_URL" \
MCMODS_TEST_DATABASE_URL="$AUDIT_TEST_DATABASE_URL" \
go test -race ./internal/httpapi \
  -run '^TestAuditCMP003ReviewResultNotificationSharesPublicationDecisionHTTPPostgresIntegration$' \
  -count=1 -v
```

无数据库迁移、现有事件格式变化或数据删除。先更新所有 API 实例，才能依赖所有新审核决定具有该保证；旧实例仍有提交后丢失通知的窗口。回滚代码会重新开放该窗口，不能删除已经存在的意图、通知或审核历史。

存量中，“已有审核决定但当前看不到对应通知意图/通知”仅是待核对候选。outbox 保留策略、通知删除和账号删除也会形成这种表象，旧事件还没有精确绑定修订 ID。必须关联不可变审核记录、历史事件与保留/投递记录，才能认定缺失；不得根据不存在的当前行直接重发通知或重放经验、货币及任务奖励。没有执行生产扫描、回填或补偿。
