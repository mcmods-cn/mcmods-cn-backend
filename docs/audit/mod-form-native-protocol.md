# Mod 表单与修订的原生浏览器夹具

`TestAuditLiveModFormFixture` 仅在 `MCMODS_RUN_LIVE_MOD_FORM=1` 时运行。使用新的
绝对 `MCMODS_AUDIT_MOD_FORM_DIR` 和实际提供页面的干净
`MCMODS_AUDIT_FRONTEND_REPO`。前端网关固定为本任务的 `3531`，Next 使用 `3532`；
API 监听隔离随机端口，准确三仓库提交、数据库 schema 和进程所有权写入运行时文件。
普通编译时的 SKIP 不是业务通过。schema 建表与清理取得任务 PG 锁，页面服务期间释放。

运行时包含三条独立的修订用例：正确答案、错误答案、取消。每个普通作者先经真实
HTTP 创建自己的 Mod，再由独立审核员通过 Mod 专用审核接口批准。作者只有自己项目
的明确编辑权限。初始正文互不相同；另一个普通用户的真实成功提交产生正常重复内容
指纹，随后独立的同项目 probe 证明默认规则会返回 `428/challenge_required`。
probe 不预热浏览器作者，也不写入指纹、强制风险状态或限制规则。保留 proof 默认
600 秒有效期、800 毫秒表单年龄及实际阈值。

另有八个内容语言乘四种输入变体，共 32 个预声明的独立创建用例：全部本地化可选值
为空、仅名称且正文为空、名称加摘要、默认语言名称加另一语言的正文。每人仅创建自己
唯一的用例项目。非法输入由原生 UI 提交前拦截；合法值必须通过实际表单输入生成，
不能直接修改 React 状态或用拼接 JSON 代替填写。全部可选值为空时，当前契约只允许
将原已填 primaryName 用作默认名称回退，不能补造其他语言的名称或正文。

认证只写 `.private/auth.json`，权限 `0600`。不要将运行时及认证文件加入证据包。
原生驱动记录每条请求的原始 body SHA、UI 提交前校验及实际页面结果，不输出认证。
服务端观察器仅记录路径、响应状态、错误代码、请求 ID、body/content SHA，以及幂等键
和 client ID 的哈希；不保存请求正文、proof 答案或 bearer 值。

页面成功创建待审修订后，驱动写入
`review-request.<caseId>.json`，内容为 `{caseId,siteId,bodySHA256}`。
夹具核对该哈希确实对应实际 `201`、声明作者及唯一待审修订，再使用一个普通独立
`content.review` 审核员执行
`PATCH /api/v1/mods/{siteId}/revisions/{revisionId}`。它保留真实审核限额，遇到 `429`
按正数 `Retry-After` 自然等待，不切换管理员或临时增权。批准结果写入
`review-result.<caseId>.json`。通用 `content-revisions` 审核入口不支持 Mod，不能替代
该专用接口。创建表单如遇真实限流，也应保留同一输入并在实际等待后由用户显式重试。

`done.flag` 只是同步信号。夹具另行核对 32 项公开内容、独立审核事件、合法空值、没有
新增未填译文，以及三条修订的真实追加数量 `1/0/0`。正确 proof 必须保持原始请求体、
幂等键和 client ID；错误答案必须绑定具体 `challenge_failed` 事件，不能将任意错误
算作通过；取消和错误答案保持初始公开正文及发布指针。默认反滥用设置须与启动时相同。
完整原生 UI 报告与 PostgreSQL 终态报告分别验收，不从测试退出码推断全部业务成功。

未完成时可在核验所有权后写 `STOP`，夹具清理自有资源并保留未完成结果。不得强杀
其他任务进程或清理归属不明的资源。本夹具不声明 NATS、真实游戏、生产数据修复或
全项目发布验收。
