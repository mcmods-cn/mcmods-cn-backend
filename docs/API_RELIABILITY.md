# API、资源可见性与异步任务约定

## 认证与权限变更

签名/session 确认无效返回 `401`。数据库、会话查找或权限缓存的运行故障返回 `503`，不清除仍可能有效的客户端登录状态。required 和 optional 认证均拒绝在该故障下继续执行业务。

用户权限的完整替换与线路升降级先在同一事务锁定 `users`，再读取和修改绑定。绑定触发器负责同事务递增 `permission_version`；提交后更新共享版本指针。线路变更读取、审计和写入失败都回滚。权限节点的新增/更新也和审计写入共同提交。

`permissions` 中的 `group.<role>` 表示完整替换后的角色集合：仅 `allow:true` 授予该角色，`allow:false` 不授予。角色绑定目前不支持 `expiresAt` 或 `context`，携带这些字段返回 `400`，避免临时/限定请求静默变成永久全局权限。临时直接权限节点继续支持原有有效期和上下文字段。

后台 SMTP 保存配置不修改共享 Server 的初始 Mailer。请求从服务端已保存配置构建当前 Mailer；`enabled:false` 即使填写了 host/from 也保持禁用。密钥仅在服务端加密设置中保存。

## 收藏与关联资源

收藏夹归属/私有访问仅授权收藏夹本身。收藏写入和历史条目读取仍分别核实资源可见性：模组/整合包已批准或由当前请求者提交；蓝图未删除且已批准/无需审核，或属于请求者/允许管理访问。公开收藏夹的公开读取只展示已公开资源，不附带该用户自己的待审内容。

同一用户的完整收藏成员集合替换通过用户行锁串行执行。不存在或不属于请求者的收藏夹返回 `400`，不会清空旧集合后报告部分成功；重复夹 ID 只处理一次。后续资源撤回、删除或改为待审时，历史条目仍经过读取过滤。

社区公开关联仅从已批准的模组/整合包/资料项目读取名称、slug 和公开 ID。旧关联指向未公开项目时不返回其数据库元数据；原有未解析的输入标识仍保留。社区封面读取只使用活动且查杀状态为 `clean` / `trusted_generated` 的文件。

社区资源引用与 `resourceId` 筛选复用公共目录的可见性条件。待审或撤回资源不经公开帖子返回名称、公开 ID、语言词条、版本和图片路径，也不借筛选结果暴露关联。资源版本只取活动且父模组已批准的来源，导入快照只取活动且可用的批准父项目来源，语言名称只取已批准译文。原始未解析输入继续保留。

公开角色资料中的嵌套皮肤/披风也使用请求者的资源权限：仅活动资源，资源所有者/管理员，或已批准且非 private 的资源。不能通过公共角色资料绕过皮肤详情权限。Yggdrasil 纹理协议的内容寻址设计仍单独适用。

## 模组内容与修订读取

公开读取版本、模板、分类、资源详情、相似资源和修订记录，先验证父模组：已批准、实际提交者、具有该项目编辑权限或已有审核/管理权限之一。只解析出 slug/public ID 并不授予待审父项目的子内容读取权；对无权限者返回 `404`。身份解析仍独立于鉴权，原编辑/审核权限契约保持兼容。

列表只有完整读取且 `Rows.Err` 为空时返回成功。编辑/删除读取的真实缺失保留 `404` 或已有输入校验语义；数据库故障返回有界 `500`，不会提示错误的“资源消失/冲突”。已持有事务的审核配置和资源身份读取使用该事务，避免小连接池自阻，并能读取同事务尚未提交的事实。合法冲突、无效引用和内容版本冲突仍分别使用原 `409` / `422` 响应。

社区创建和编辑也通过当前事务读取审核配置，列表在持有结果流前读取图片配置。社区编辑及翻译请求/结果的数据库故障返回 `500`，真实缺失和无权限仍保留原有响应。读取翻译缓存失败时不视为缺失并创建新任务；completed 结果解析或读取失败也不返回假成功。

压缩响应的 `FlushError` 传播 gzip 写入和底层连接 flush 错误，供 SSE 等流式端点终止失败连接；兼容的 `http.Flusher` 仍委托同一实现。

## 皮肤与蓝图多语言编辑

皮肤 metadata PUT 可在同一请求提交：

```json
{"defaultLocale":"zh-CN","localizations":[{"locale":"zh-CN","name":"名称","summary":"简介","contentMarkdown":"正文"},{"locale":"en-US","name":"Name","summary":"Summary","contentMarkdown":"Body"}]}
```

提交的语言必须合法且规范化后不重复，defaultLocale 必须出现在具备名称的提交项中。皮肤名称不超过 80 个 Unicode 字符、简介不超过 1000 个字符。省略整组多语言字段继续使用旧 metadata 请求行为。

所有语言与 metadata 保存在一个不可变审核快照，经批准后同事务发布；不会因第一次逐语言提交产生待审锁而让剩余语言失败。蓝图采用同样的单请求语言集合提交。语言集合是 **合并更新**：未提交的人工译文保留；相同内容不制造新版本；改动 AI 译文使用共享发布规则转为 `human_corrected` 并递增原修订号。当前接口不把省略或空名称解释为删除语言。

## 导入、转换与翻译任务

元数据导入的领取、进度、失败与完成使用 `status='running'` 和领取时的 `started_at` 共同约束。迟到 worker 不得覆盖新领取结果；数据库故障不是可 ACK 的“无任务”。启动时和周期巡检回收超过现有五分钟窗口的导入；外部 HTTP 使用配置超时，重定向不得改变 host 或协议（包括 HTTPS 降级为 HTTP）。专用客户端不继承环境代理，防止目标 IP 校验被代理绕过；配置和部署边界见 [项目自动更新设计](../PROJECT_AUTO_UPDATE_DESIGN.md)。

开启 NATS outbox 时，蓝图上传的 original variant、normalize job 与 outbox 消息共同提交。消息写入失败回滚整个上传完成事务；重复完成已 queued 的上传不重复创建任务。软删除蓝图的格式下载在 URL 签名前返回 `404`。

社区翻译入队冻结源修订、目标语言和术语表上下文，在同事务内预留现有站点/用户额度并写入任务及 outbox。发布前锁定任务和活动、已批准的社区源文，要求任务仍 running 且源修订一致；合格译文与 completed 状态共同提交。取消、删除、撤回、源文变更及迟到重复发布不写入译文。标题不能为空；原正文非空时译文也不能为空；标题单独存在的原文允许空正文。其他供应商解析、人工保护、额度和恢复边界见 [AI 翻译可靠性](AI_TRANSLATION_RELIABILITY.md)。

导出语言包仅使用相同规范化语言标识的来源；不能将 zh-TW 内容重新标记为 zh-CN/zh-Hans/zh-HK/zh-MO。找不到确切来源时保持原有原文回退及 provenance。

## 发布顺序和恢复

这些 API 变更不新增 schema。先发布全部后端 API、审核消费者和相关 worker，再发布使用单 PUT 语言字段的前端；滚动期间旧审核实例会忽略新快照字段，因此应先排空/升级旧消费者。旧客户端省略语言字段、已存在的旧审核快照仍兼容。数据库/AI 专项的独立前向迁移和部署要求以其正式文档为准。

新画廊归档键包含 gallery 与 file 的不可变公开 ID，见 [OSS 目录规范](oss-object-layout.md)。旧记录仍使用数据库完整 ObjectKey 访问，不在本次部署迁移或删除存量对象。

回退后端时保留已创建快照和数据库记录；未处理的新多语言快照应由支持版本的审核消费者处理，不能由旧版本静默批准。测试仅使用隔离 PostgreSQL 与确定性端点；真实供应商、生产数据库健康和 OSS 服务端复制未据此宣称验收。

项目自动更新复用既有随机租约字段，资源写入、失败及完成均复核领取和当前来源配置。租约、恢复、暂停与滚动升级要求见 [项目自动更新设计](../PROJECT_AUTO_UPDATE_DESIGN.md)；升级时必须停止旧自动更新 worker，不能混跑没有写入 fence 的旧实现。
