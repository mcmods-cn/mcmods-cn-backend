# 表情 GIF 解码安全边界

表情上传保留 PNG 与 GIF。既有权限、上传者归属、私有 OSS 读取、大小/哈希/MIME 与图片尺寸校验不变。默认压缩文件上限为 4 MiB、最长边 1024、GIF 最多 120 帧、累计解码帧像素最多 64,000,000、单轮动画时长最多 30 秒；沿已有 StickerConfig 调整限制，不能把它理解为整个进程的 RSS/CPU 上限。

GIF 在 gif.DecodeAll 分配全部帧之前先进行编码结构预检查。检查完整 header、全局/局部颜色表、graphic control 延迟、文本/应用/注释扩展、帧描述符、LZW 最小编码宽度与全部有界 sub-block。每个帧必须在逻辑画布内，并逐项累加帧数、帧面积和延迟；超过限制、越界或截断立即拒绝，不分配帧像素缓冲。预检查只按结构走编码字节，不做内容解压；通过后仍用标准 GIF 解码器验证实际像素内容，保留解码结果的限制复核。

本地确定性回归使用真正的 Go GIF 编解码器。64 个 64×64 帧的压缩样本小于实际 4 MiB 上限；分别限制帧数与累计面积，检查拒绝时不会分配完整动画。还覆盖正常双帧动画、帧面积/时长超限、逻辑/帧尺寸、graphic control 和压缩块截断。这些结果不证明所有真实 OSS 供应商行为、全站上传并发或生产内存峰值已验证。

仅部署后端代码，无 API/schema 或数据迁移。既有图片无需重写；不自动扫描、删除真实上传。最小验证命令为 `go test ./internal/httpapi -run TestStickerGIF -count=1 -v`。

公开和管理目录读取会检查数据库结果迭代错误；公开目录版本查询失败返回 500，避免将部分目录或版本 0 误报成功。隔离 PostgreSQL 回归删除该测试专属数据库的 sticker_catalog_state 表模拟元数据失败，不操作已有数据库。
