# AI 翻译任务与预算

翻译供应商默认停用。界面静态词条、已发布内容本地化、通知模板及 AI 生成译文是不同的数据来源。读取已有译文或界面构建不需要供应商密钥；公开内容缺少已支持目标语言时，只有 `ai.config.translation.enabled=true` 才自动排队，失败或取消的同源版本任务不会因刷新再次发起收费请求。显式的用户翻译请求仍使用已有权限与每日 token 额度。

## 创建与执行

管理员任务入口及内容、社区、通知入口在同一 PostgreSQL 事务内创建 `ai_tasks`、预留额度并写入已启用的 NATS Outbox。Core NATS 只是唤醒信号，worker 每 15 秒扫描最多 100 个等待任务。未启用 Outbox 时仍沿用直接发布，发布失败会留下失败任务。

`queued/retrying -> running` 使用事务和按任务类型的 advisory lock，读取实时配置的并发上限（1–32）。供应商超时配置限制为 1–600 秒；运行任务超过该超时加 60 秒被保守标记失败。崩溃时供应商可能已经计费，因此恢复不会自动再调用供应商。重复消息不能再次领取已经运行或终结的同一任务。

任务只有在输出校验和数据库持久化成功后才变为 `completed`；内容、社区、通知的发布和 completed 在同一事务提交。取消先取得任务锁并提交时禁止发布；发布先提交时 cancel 返回409，不能出现取消成功但刚发布的窗口。内容开启 AI 审核时，完成表示已建立待审核修订，发布仍要等待审核。通知、社区及目录在写入事务里锁定任务，取消后的迟到响应不能发布。供应商返回的用量仍会记录在取消或失败任务上。

## 版本与人工保护

目录任务冻结资源类型/公开 ID、源语言/源修订号、目标语言/目标修订号。执行前、结果写入和待审核修订最终发布时重新核对。持久化还锁定真实资源状态，治理审核/删除并发提交后不能使用先前可见性继续发布。`human`、`human_corrected` 译文不会被 AI 覆盖；旧任务没有目标版本快照时仅能创建不存在的目标。

人工批量发布先读所有旧语言版本，再发布发生变化的语言，最后使其剩余旧 AI 派生投影失效。相同正文不会增加版本或触发重译。同批源文与 AI 译文人工修订保留目标原修订号递增及 `human_corrected` 来源。修订历史保留在不可变的 `content_revisions` 中。

社区任务按帖子公开状态及发布修订核对；该模型目前没有人工译文编辑路径，不能宣称存在额外人工保护元数据。通知冻结 `updated_at`、源语言和标题/正文快照，并在写入时核对收件人范围。读取翻译结果只读当前数据库译文，不通过轮询重新写入已过期任务结果。

## 输出与供应商边界

每批最多 100 个条目，源请求至多 1 MiB，管理员 prompt 和术语表各至多 1024 字节；输出 token 使用模型配置且最多 8192。模型声明上下文窗口时，超过保守预留估算的请求会停止。

任务冻结术语表及 SHA-256 指纹，去重 key 包含术语版本；重试沿用快照，后续配置变更不修改已预留任务。供应商只接收语言、条目及术语表，不接收资源/收件人 ID、额度或任务 metadata。术语表作为翻译数据传入，不开放工具或执行能力；输出仍必须通过结构和受保护片段校验。

响应必须是单个完整 JSON 对象（允许完整 JSON 代码围栏），拒绝多余解释、重复 JSON 字段、缺失/重复条目、未知字段、非字符串、必要字段空值和明确的输出截断。条目标识和字段只来自源请求，校验简单 `{identifier}`/`{{identifier}}` 插值、代码片段及 HTTP(S) 链接的多重集合。站点静态界面使用自有简单插值格式，并非 ICU；这不代表完整 Markdown 结构、所有语种或真实翻译质量已验证。

HTTP 响应限制为 8 MiB；错误不保存供应商响应正文。URL 拒绝协议之外的地址、URL 用户凭据、query 和 fragment；请求继续复用统一提供方客户端的 DNS 私网过滤和同源重定向规则。该统一客户端允许显式 loopback 提供方，部署时应只授予可信管理员 `ai.write` 并核实代理与本地服务边界；本地 mock 验证不代表生产 SSRF 边界全面验收。

## 额度及费用

站点 `hour/day/month` 请求数、token 和 CNY 费用限额按 UTC 窗口，在同一全局 advisory lock 下预留。普通用户继续使用 `user.ai.daily_token_limit`。预留是保守估算，包含 UTF-8 源请求字节、最大输出和固定 prompt 开销；估算不是供应商真实 token 用量。

费用按管理员维护的每百万 token CNY 单价估算，不使用本次审计猜测的供应商价格。开启正数费用预算时，模型必须配置正数有限价格，缺价时拒绝新收费任务。请求失败且 usage 未知时保留预留；运行中取消同样保留，取消未开始任务可以释放 token/费用预留。已知失败或取消用量仍计入额度。`cost_micros` 是配置单价与 usage 的估算，不是供应商账单。

`quotas` 当前只支持 `scope=site`、`subject=default`（兼容空 subject）。配置保存及任务执行拒绝其他 scope/subject、不支持周期和负限额，错误为 `AI_CONFIG_INVALID`，避免配置静默失效；用户/角色新预算标识与合并规则仍需产品定义。个体每日 token 权限独立有效。管理员 retry 保留原任务创建者，通知和 quotaBacked 内容会通过既有 uncached RBAC 解析原创建者当前 daily token 权限，在同一事务重新预留额度；已停用创建者拒绝恢复。管理员主动创建的管理任务仍按其既有管理授权使用站点预算。供应商不支持请求幂等时，崩溃窗口不能保证严格只计费一次。

## 管理恢复接口

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `POST /api/v1/admin/ai/tasks/{id}/retry` | `ai.task.enqueue` | 仅失败任务；创建新任务，HTTP 201 返回 `id/taskUid/status/retryOf`；原任务最多有一个 retry |
| `POST /api/v1/admin/ai/tasks/{id}/cancel` | `ai.write` | 活跃任务变为 cancelled；HTTP 200 返回原 `id/taskUid/status` |

请求体为 `{}`。状态不适用返回 409；额度不足返回 429；源或目标变更需创建新任务。关键稳定错误码为 `AI_TASK_INACTIVE`、`AI_TASK_NOT_FAILED`、`AI_SOURCE_CHANGED`、`AI_QUOTA_EXCEEDED`、`AI_RETRY_EXISTS`、`AI_ACTOR_UNAVAILABLE`。后台操作会记录审计日志。重试和运行中取消均提示供应商可能已计费；重试会增加费用，不能展示成免费恢复。

## 验证边界

确定性本地 HTTP 测试覆盖正常响应、无效 JSON、缺条目/字段、空内容、重复字段/条目、变量/代码/链接破坏、输出截断、超时、429、503 和 URL 凭据泄漏拒绝。真实隔离 PostgreSQL 验证并发领取、额度预留、Outbox 同事务、取消后用量、崩溃任务转失败、目录待审核发布双版本/人工保护、根分类唯一/并发祖先循环及并发重复迁移。

`ai_failure_scenarios_integration_test.go` 使用 ownership marker 核验的独占 PostgreSQL 数据库及本地 HTTP 端点，实际执行 worker/配额/持久化链：断连、配置 1 秒超时、调用者取消后恢复，均不自动再次请求；未知 usage 保留 token 与费用预留，不能当免费释放。五种损坏批次（空内容、缺字段、缺条目、占位符破坏、无效 JSON）整体失败，不发布其中合格的一项、不破坏已有通知译文，仍记录供应商回传的合成 usage。消息处理前关闭模型，在执行阶段实时拒绝调用，HTTP 请求数为零；当前领取仍先进入 running 再记录 failed，没有宣称模型停用使任务保持 queued。

上述 3 组 9 个场景通过真实 PostgreSQL `-race`。首版本地端点未消费请求体，导致服务端取消观察失败；修正端点后重新执行，过程记录保留，未把测试设置错误称为产品回归。源文/人工版本保护、并发消息只请求一次及取消/发布排序引用 `ai_task_integration_test.go` 的相应用例，种子 run 保护引用 `seed_crawler_ai_integration_test.go`。当前没有每种语言的独立 enabled 状态模型，不能发明“语言停用”策略或虚构其竞态已通过；此项为不适用，目标语言配置控制新自动任务的范围。

未发送真实付费请求，没有验证真实供应商连通性、语义质量、实际 token 计费或生产数据库状态。真实多实例长时间故障注入尚未执行；本地可控 HTTP 的结果不等于这些运行结论。

种子爬虫同样复用 `ai_tasks`、全局并发、Outbox 和站点预算，额外校验真实 run 随机租约、候选/元数据导入任务归属及源文哈希，并在事务内预留爬虫 UTC 日额度。未知 usage 的失败保留估算，原快照恢复不会自动再次付费；结果通过现有编辑器本地化字段进入草稿和自动提交。详见 `../SEED_CRAWLER_DESIGN.md`，其独立表模型与 Mod 版本模型的差异没有被隐藏。

已完成种子 run 的失败译文也可通过上述显式 retry 恢复：创建新的专用 run/随机租约与普通 AI 任务，旧 run 与费用事实保留；仅更新原owner名下仍有效、未提交的绑定草稿。源文哈希、草稿哈希/updated_at 和真实资源ID在执行前/发布时再次核对，已有目标或期间人工编辑拒绝覆盖。仅追加该目标 `localizations`，不自动创建公开项目或提交。三类预算（site、crawler、原actor）同事务预留，未知费用保守保留，失败不自动二次请求；终态清理暂时失败由既有扫描补偿。历史缺草稿ID仅在原run时间/归属证据可验证时补绑定，其余409。

管理 AI 配置 GET/PUT 在数据库、encrypted envelope 或解密JSON损坏时返回503 `AI_CONFIG_UNAVAILABLE`，不把读取失败伪装为默认配置或据此保存空secret；缺少配置行仍使用原有停用默认值。执行路径沿用停用默认值保守停止新调用。真实 PostgreSQL 回归验证坏envelope、坏明文JSON、关pool和缺row；恢复场景见 `seed_crawler_recovery_integration_test.go`（19项，本地HTTP/真实PG）。
