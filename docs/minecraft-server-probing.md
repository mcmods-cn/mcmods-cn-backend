# Minecraft 服务器探测

仅已通过审核且 `next_probe_at` 到期的服务器进入定时探测。调度器在启动后等待 15 秒，随后按原有五分钟周期运行；每次通过事务、行锁和 `SKIP LOCKED` 领取最多 1000 项，并将领取时间推进五分钟。正常单调度循环会等待当前批次结束。

所有定时调度调用在同一进程中共享 32 个探测名额。并行调用或意外重复启动调度器不会把进程并发预算叠加。数据库领取负责避免同一服务器在同一周期重复执行；不同进程仍各有 32 个名额，这不是跨部署实例的全局并发限制。配置协议发现另有独立的四个进程内名额及既有网络、包大小和解析预算，不能用它代替定时探测的并发限制。

等待名额的工作响应上下文取消；领取名额后再次核实取消状态，避免取消后开始新的网络请求。已进入探测的工作沿原上下文退出，每条路径都释放名额。名额覆盖探测及其持久化过程，因此同一进程的探测与数据库结果写入合计也受 32 个在途任务约束。

领取先于探测提交。若进程退出或工作取消，已领取但未执行的项目保留原有五分钟延后，后续周期再领取；当前实现没有跨实例租约回收或严格只执行一次的保证。网络探测成功后，状态采样、最新状态和机器模组快照在同一事务中写入；离线错误最多保存 2000 字节。历史采样按配置保留天数清理。

本次修复没有 API、schema、领取数量、周期或网络超时变更，不需要数据库迁移。按通常应用升级顺序部署即可；旧进程继续使用每次调用独立的并发预算，只有更新后的进程具备共享名额保护。

## 验证

`TestTEST015SchedulerConcurrentClaimsPersistSnapshotsAndRespectConcurrencyIntegration` 保留原有 48 项、双调用、32 并发、去重、状态采样和快照断言。新增 `TestOCT03ServerSchedulerSplitClaimsShareProcessProbeBudgetIntegration` 在隔离 PostgreSQL 中先锁住后一半项目，强制形成两批已提交的 24 项领取，验证共享上限以及每项恰有一条可持久化结果。

`TestOCT03ServerSchedulerCancellationReleasesProcessProbeBudgetIntegration` 在 32 个名额已占满时取消另一批已领取工作，验证其未调用探测依赖、可正常结束，并在下一周期重新达到完整 32 个名额。用例只控制探测函数，数据库事务、领取、快照和结果持久化使用实际 PostgreSQL；真实 Minecraft 服务、生产数据库及部署容量不在这些模拟探测结果的验证范围内。
